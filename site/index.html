Engineering highlights

Real browser where it is needed

React and Nuxt sites render their content in JavaScript, so they are opened in headless Chromium. Images, fonts and media are blocked to keep it fast.

One row per movie and location

Chains that list movies globally open each movie page to find its cinemas. Coming-soon entries are de-duplicated against today's programme.

Fault isolation

A failing site only loses its own cinema; the rest of the run continues. Detail pages are retried once.

Debug snapshots

When a Playwright page fails, its HTML and a full-page screenshot are saved to scraper-debug/ - usually enough to see whether a selector changed or the request was blocked.

Original titles

Extracted wherever the site has them; they make matching a movie against databases like TMDB far more reliable than local titles.

Coordinates

Every location has coordinates, so results can be sorted by distance from the user.

Try it

Docker no JDK or browser setup

docker build -t movienee-scrapers .
docker run --rm --ipc=host movienee-scrapers --cinema arena
docker run --rm --ipc=host -v "$PWD/output:/output" \
  movienee-scrapers --json results.json

Gradle JDK 21

./gradlew playwrightCli --args="install chromium"
./gradlew run --args="--cinema roda --date 2026-10-10"
--cinema <name>only this chain (repeatable)
--date <yyyy-MM-dd>programme date (default today)
--json <file>also write results as JSON

Data model

Every scraper returns a list of ScrapedMovie - one entry per movie and cinema location. Full API docs →

FieldTypeMeaning
titleStringTitle as shown by the cinema (usually Serbian)
originalTitleString?Original title, when the site provides it
cinemaNameStringChain, e.g. Cineplexx
cinemaLocationStringLocation, e.g. CINEPLEXX 4D DELTA CITY; Coming soon when none is scheduled yet
latitude, longitudeDouble?Coordinates of the location
bookingUrlStringLink to the movie on the cinema's website
isUpcomingBooleanComing soon rather than now showing
